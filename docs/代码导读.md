# 局域网聊天程序 代码导读

本文按“程序怎么跑起来”的顺序介绍模块划分和主要调用链，适合第一次阅读本项目源码时使用。运行方式见 [README](../README.md)，测试说明见 [测试说明](test/测试说明.md)。

## 一、整体结构

程序由一个服务器进程和任意多个客户端进程组成。

- 服务器监听 TCP 9527，处理登录、消息转发、聊天记录、文件传输和撤回等请求。
- 服务器同时监听 UDP 30000，应答客户端的局域网发现广播。
- 客户端使用 Swing 绘制界面，通过 TCP 长连接与服务器通信。
- 用户、聊天记录、文件传输日志存入 MySQL。
- 消息在网络上是 `Message` 子类的 Java 对象，通过 `ObjectOutputStream` 和 `ObjectInputStream` 传输。

两个入口：

| 入口 | 类 | 说明 |
|---|---|---|
| 服务器 | `com.chat.server.ChatServer` | 打开图形控制台，点击启动后开始监听 |
| 客户端 | `com.chat.client.ChatClientApp` | 打开登录窗口，加 `--local-server` 可在本机同时启动服务器 |

## 三、服务器启动

`ChatServer.main` 创建服务器实例并打开 `ServerUI`。用户点击启动后执行 `ChatServer.start()`：

```
start()
├─ 检查 security.message.secret 非空
├─ 初始化 UserService、MessageService、FileLogService
├─ 检查数据库可用性
├─ 创建管理员账号（admin 不存在且配置了口令时）
├─ 注册智能助手虚拟用户（配置齐全时）
├─ 绑定 ServerSocket
├─ 创建连接线程池
├─ 启动接受连接线程
├─ 启动 DiscoveryResponder
└─ 启动心跳扫描任务
```

连接线程池的核心线程数为 0，最大线程数取 `server.max.connections`，使用 `SynchronousQueue`。每个连接线程会阻塞在 `readObject` 上，因此不为空闲连接长期保留线程。

## 四、连接与登录

客户端：

```
ChatClientApp.main
└─ LoginUI
   ├─ DiscoveryClient.discover() 或手动填写地址
   ├─ ChatClient.openConnection(host, port)
   │  ├─ 建立 Socket
   │  ├─ 创建对象输入输出流
   │  ├─ 安装 MessageFilter.forClientInput()
   │  └─ 启动接收线程、发送线程池、ACK 扫描和心跳
   └─ ChatClient.login(username, password)
      └─ 发送 LOGIN，正文为“用户名|密码”
```

服务端：

```
ClientHandler.run
└─ dispatch
   └─ handleSystemMessage
      └─ handleLogin
         ├─ 校验字段数量与字符集
         ├─ UserService.login 校验口令与锁定状态
         ├─ UserManager.register 检查重复登录
         ├─ 返回 LOGIN_RESULT
         ├─ 广播系统通知和在线用户列表
         ├─ 下发会话令牌
         └─ 补投离线消息，最多 200 条
```

登录成功后客户端打开 `ClientUI`，并把它注册为 `ChatListener`。

## 五、私聊

发送端：

```
PrivateChatPanel.doSend
└─ ChatClient.sendPrivateTextReturningId
   ├─ 创建 TextMessage，类型 TEXT_PRIVATE，生成 messageId
   ├─ 记录到待确认表
   └─ 写入对象流并 flush
```

服务端：

```
ClientHandler.handleTextMessage
├─ requireLogin 检查登录态
├─ 校验消息类型与正文
├─ 强制覆盖 sender 为登录用户名
├─ 校验引用，必要时清空
├─ 接收者为 ai 时交给智能助手
├─ 按 messageId 判重
├─ UserManager.sendTo 定向发送
├─ MessageService.saveMessage 落库
├─ 按结果回 MSG_ACK：DELIVERED、OFFLINE、DUPLICATE 或 FAILED
└─ 向发送方回显摘要
```

在线投递成功时，服务端在发送后立即把记录标记为已投递，并向发送方回 `DELIVERED`。接收方离线时记录以未投递状态入库，等接收方下次登录补投，客户端收到补投消息后再回 `MSG_ACK`。

接收端：

```
ChatClient.receiveLoop
└─ readObject
   └─ handleIncoming
      ├─ 处理 HEARTBEAT_ACK、MSG_ACK、SESSION_RESUME
      ├─ 离线消息先回 ACK，再按 messageId 去重
      └─ notifyMessage 回调 ClientUI
         └─ 切换到 EDT 后交给私聊窗口
```

`messageId` 是跨端稳定标识，数据库自增 `id` 只用于本地排序和分页。

## 六、群聊

发送端调用 `ChatClient.sendGroupText`，消息类型为 `TEXT_GROUP`，接收者为空串。

服务端在 `handleTextMessage` 中判断群聊类型：

```
UserManager.broadcastText 广播给全部在线连接
MessageService.saveMessage 落库
```

客户端收到后交给 `GroupChatPanel`。窗口未打开时只累计未读，不弹出窗口。用户上线和下线由服务端广播 `SYSTEM` 与 `USER_LIST`。

## 七、文件传输

文件传输由五类消息组成：

```
FILE_REQUEST   发送方 → 服务器 → 接收方
FILE_ACCEPT    接收方 → 服务器 → 发送方
FILE_CHUNK     发送方 → 服务器 → 接收方，重复多帧
FILE_END       发送方 → 服务器 → 接收方
FILE_RESULT    接收方 → 服务器 → 发送方
```

发送方：

```
FileTransferUI 选择文件
└─ ChatClient.sendFile
   ├─ FileService.prepareSend 检查文件、计算分块数与 SHA-256
   ├─ 登记待发送记录
   ├─ FileTransferCodec 编码请求
   └─ 以 FILE_REQUEST 发送
```

服务端 `handleFileMessage` 校验发送者、接收者、传输编号和文件大小，然后用 `TRANSFER_REGISTRY` 登记传输会话。只有登记过的参与者和合法状态转换才能继续转发。

接收方同意后，`FileService.openReceive` 在 `data/received` 创建目标文件，重名时自动加序号。收到分块后按序号写盘，收到 `FILE_END` 后校验 SHA-256，并回 `FILE_RESULT`。

服务端在结束时向 `chat_message` 写文件消息记录，向 `chat_file_log` 写传输日志。文件内容只经过服务器中继，不写入服务器磁盘。

## 八、历史查询、搜索与导出

历史查询由私聊窗口打开时触发，也用于向上翻页：

```
ChatClient.requestHistory(peer, from, to, cursor, limit)
└─ HISTORY_REQUEST
   正文：target|from|to|peer|cursor|limit
```

服务端忽略请求中的 target，查询对象固定为登录用户名。`MessageService.queryPage` 按发送者、接收者、对端、时间范围和游标组装查询，按主键倒序取一页。

响应正文格式：

```
1|<条数>|<peer>|v2
#beforeId=<本页最小主键>
时间|发送者|接收者|messageId|内容
```

`v2` 表示记录行的字段格式。`#beforeId` 单独占一行，客户端据此继续向前翻页。

搜索由 `SEARCH_REQUEST` 触发。正文以密文入库，SQL 无法直接匹配，因此 `MessageService.search` 先查出本人可见记录，再在应用层解密匹配。

导出由聊天窗口工具条触发：

```
ChatClient.requestExport(scope)
└─ EXPORT_REQUEST
服务端查询本人可见记录，按会话范围过滤，MessageExporter 渲染
└─ EXPORT_RESULT
客户端弹出原生保存对话框并写入文件
```

## 九、消息撤回

```
消息气泡右键撤回
└─ ChatClient.requestRecall(messageId)
   └─ MSG_RECALL
服务端 handleRecallRequest
├─ 按 messageId 查询记录
├─ 校验请求者是发送者
├─ 校验是否在 2 分钟内
├─ 更新 recalled 并替换正文
├─ 返回 MSG_RECALL 回执
└─ 私聊通知对端，群聊广播给其他在线用户
```

撤回后，历史查询、搜索和导出都读取占位文本，不返回原文。

## 十、心跳、重连与离线补投

心跳：

- 客户端每 15 秒发送 `HEARTBEAT`，服务端回 `HEARTBEAT_ACK`。
- 服务端每 20 秒扫描连接，60 秒没有活动的连接判定掉线。
- 任意消息都会刷新最后活跃时间。

重连：

```
接收线程读失败
└─ handleConnectionLost
   ├─ 主动退出时直接结束
   └─ 否则启动重连线程
      ├─ 指数退避
      ├─ 重新建立连接
      └─ 携带会话令牌发送 SESSION_RESUME
         ├─ 令牌有效：恢复登录态并续期
         └─ 令牌过期：提示重新登录
```

会话令牌只保存在服务器进程内存中，进程退出即失效。控制台的停止与启动只断开连接、不清空令牌表，客户端在令牌有效期内重连可以恢复会话；令牌过期或服务器进程重启后，客户端回到登录界面重新登录。

离线补投：

```
接收方离线
├─ 消息落库，delivered=0
├─ 发送方收到 OFFLINE 回执
接收方下次登录
├─ 查询未投递消息，最多 200 条
├─ 逐条发送 OFFLINE_MESSAGE
├─ 客户端回 MSG_ACK
└─ 服务端标记已投递
```

## 十一、反序列化限制

`MessageFilter` 在类型白名单之外限制每条消息的资源消耗：

- 服务端：每条消息 1MiB、20 万引用。
- 客户端：每条消息 64MiB、800 万引用。
- 白名单：`com.chat.common.*;java.lang.*;java.time.*;java.util.*;!*`。
- 最大深度 8，单数组最大 65536。
- 每次读取对象前调用 `beginMessage()` 重置预算基线。

客户端预算更大，用于承载用户列表、历史记录和导出结果。

## 十二、局域网自动发现

```
DiscoveryClient.discover
├─ 向广播地址发送 LANCHAT_DISCOVER
├─ 向 127.0.0.1 再发一次
└─ 收集 LANCHAT_ANNOUNCE|ip|port|在线人数
```

服务端 `DiscoveryResponder` 返回本机地址、端口和在线人数。广播被网络环境屏蔽时，客户端可以手动填写服务器地址。

## 十三、智能助手

配置 `ai.workflow.id` 与 `ai.api.token` 后，`ChatServer.registerAiAssistant()` 注册一个虚拟用户 `ai`。虚拟用户不占连接，也不计入在线人数。

```
用户私聊 ai
└─ ClientHandler.handleTextMessage
   └─ ChatServer.askAi
      └─ AiAssistantService.ask
         ├─ 按提问者限频，3 秒一次
         ├─ 线程池异步发送 HTTP 请求
         ├─ 限制响应体大小
         ├─ JsonCodec 解析响应
         └─ 以 ai 身份回一条私聊
```

令牌只放在请求头，异常信息写入日志前会脱敏。给 `ai` 发送文件会直接返回提示，不触发外部请求。

## 十四、阅读顺序

1. 先看 `common` 下的 `Message`、`TextMessage`、`FileMessage`、`MessageType`，理解协议对象。
2. 再看 `ChatServer` 与 `ClientHandler`，理解服务器如何接受连接和分派消息。
3. 然后看 `ChatClient` 与 `ClientUI`，理解客户端如何收发和路由消息。
4. 按需要看 `MessageService`、`FileService`、`UserService` 和对应的 DAO。
5. 最后看 `BaseChatPanel`、`MessageBubble` 等界面类，理解消息如何呈现。
