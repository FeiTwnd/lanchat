# 局域网聊天程序 测试说明

本文件是本项目测试工作的唯一说明文档，覆盖**测试策略、环境准备、编译与运行命令、单元测试用例、集成测试用例、覆盖矩阵与判定标准**。

本文件不记录历史执行结果、缺陷流水与截图。原因有两点：一是课程交付需要的是"测试怎么跑、覆盖了什么、怎样算通过"，而不是一轮轮开发过程的现场记录；二是把结果写死在文档里，代码一改就会失真。需要结果时按本文命令现场运行，以运行输出为准。

> 对应旧文档：原 `docs/test/测试报告.md` 与 `docs/test/测试用例表.md` 已合并到本文件，旧文件已从仓库移除。

## 一、测试目标与范围

### 1.1 目标

1. 验证题目要求的四项核心功能：**局域网自动发现、私聊、群聊、文件传输**。
2. 验证课程要求的支撑功能：注册登录、在线用户列表、消息持久化、历史查询、导出、撤回。
3. 验证非功能要求：多线程并发、断线重连、消息可靠性、输入校验与安全边界。
4. 用可重复执行的用例固定关键行为，避免后续改动悄悄破坏既有功能。

### 1.2 范围

| 层次 | 覆盖对象 | 不覆盖 |
|---|---|---|
| 单元测试 | 工具类、实体与编解码、DAO、Service、文件分块协议、反序列化过滤器 | Swing 界面像素、真实网络 |
| 集成测试 | 真实 `ChatServer` + 多个真实 `ChatClient` 的端到端链路 | 界面点击、窗口渲染 |
| 人工验收 | 界面布局、原生文件对话框、多机联调、演示流程 | 不进入自动化统计 |

界面相关的人工验收步骤见 `docs/用户手册.md`；本文只负责可自动执行的 57 条单元测试与 10 条集成测试。

## 二、测试策略

### 2.1 为什么不用 JUnit

课程要求"单元测试 + 集成测试"，并未限定框架。本项目选择零依赖的自研框架：

- 项目本身不使用 Maven/Gradle，引入 JUnit 需要手工下载并管理多个 jar，换一台机器就可能跑不起来；
- 自研框架只有一个注解加一个反射运行器，任何 JDK 17+ 环境都能直接编译运行；
- 运行输出就是用例清单，便于与本文档逐条对照。

这不是"为了省事不做测试"：57 条单元测试与 10 条集成测试都是真实断言，不是打印后人工目测。

### 2.2 三层分工

| 层次 | 做法 | 能发现的问题 |
|---|---|---|
| 单元测试 | 直接 new 被测对象，必要时用临时目录或测试库；不发网络包、不启动界面 | 算法错误、边界条件、SQL 映射、编解码不一致、异常分支 |
| 集成测试 | 真实启动服务器，用真实 `ChatClient` 连接，走完整协议 | 协议字段、线程时序、广播范围、离线补投、文件中继、撤回权限 |
| 人工验收 | 按用户手册操作真实界面 | 布局、字体、原生对话框、多机网络差异 |

### 2.3 隔离原则

- **数据库隔离**：测试永远不连开发库 `lanchat`。`TestDatabase` 把 `db.url` 中的库名替换为 `lanchat_test`，并附加 `createDatabaseIfNotExist=true`；每个用例开始前清空 `chat_user` 与 `chat_message`。
- **文件隔离**：接收文件、导出文件写入系统临时目录，用例结束删除。
- **网络隔离**：集成测试用 `ServerSocket(0)` 让操作系统分配空闲端口，避免与正在运行的 9527 端口冲突。
- **配置隔离**：可用系统属性 `-Dlanchat.test.db.url=...` 指向另一个库，便于并行执行多轮测试。

## 三、环境准备

### 3.1 必需环境

| 项目 | 要求 |
|---|---|
| JDK | 17 或更高（开发与验证使用 OpenJDK 21） |
| MySQL | 8.x，可连接；测试账号需要有建库、建表、TRUNCATE 权限 |
| 操作系统 | Windows / Linux / macOS 均可 |
| 图形环境 | 单元测试与集成测试**不需要**；人工验收界面时需要 |

### 3.2 准备配置文件

测试读取与服务器相同的 `config/chat.properties`。首次运行：

```bash
cp config/chat.properties.example config/chat.properties
```

至少填写：

```properties
db.url=jdbc:mysql://localhost:3306/lanchat?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
db.username=root
db.password=你的数据库口令
security.message.secret=至少32位的随机字符串
```

说明：

- `security.message.secret` 在测试中用于加解密聊天正文，必须非空；同一轮测试内保持不变即可。
- `admin.password` 可以留空，测试不依赖默认管理员。
- `ai.bot.id` 与 `ai.api.token` 建议留空，避免集成测试触发外部网络请求；留空时小助手不启用，10 条集成用例仍应全部通过。

### 3.3 测试库如何创建

不需要手工建库。`TestDatabase` 会在连接串中加 `createDatabaseIfNotExist=true`，第一次连接时自动创建 `lanchat_test`；表由 DAO 构造器中的 `CREATE TABLE IF NOT EXISTS` 创建。

如果数据库账号没有建库权限，请先手工执行：

```sql
CREATE DATABASE lanchat_test DEFAULT CHARACTER SET utf8mb4;
```

### 3.4 时区检查

`db.url` 中的 `serverTimezone` 必须是数据库所在机器的真实时区。东八区填 `Asia/Shanghai`。填错不会让测试必然失败，但会让历史查询的日期边界整体偏移，属于"测试过了、功能错了"的典型陷阱。

## 四、编译与运行

以下命令均在**项目根目录**执行。`lib/mysql-connector-j-8.2.0.jar` 已随仓库提供。

### 4.1 编译主源码与测试源码

Linux / macOS：

```bash
mkdir -p build/main build/test

find src/main/java -name '*.java' > /tmp/lanchat-main.txt
javac -encoding UTF-8 -d build/main @/tmp/lanchat-main.txt

find src/test/java -name '*.java' > /tmp/lanchat-test.txt
javac -encoding UTF-8 -cp "build/main:lib/mysql-connector-j-8.2.0.jar" -d build/test @/tmp/lanchat-test.txt
```

Windows（PowerShell）：

```powershell
New-Item -ItemType Directory -Force build\main, build\test | Out-Null

Get-ChildItem -Recurse src\main\java -Filter *.java | ForEach-Object { $_.FullName } | Set-Content main-sources.txt
javac -encoding UTF-8 -d build\main "@main-sources.txt"

Get-ChildItem -Recurse src\test\java -Filter *.java | ForEach-Object { $_.FullName } | Set-Content test-sources.txt
javac -encoding UTF-8 -cp "build\main;lib\mysql-connector-j-8.2.0.jar" -d build\test "@test-sources.txt"
```

主源码编译期只依赖 `java.sql` 标准接口，理论上不需要 JDBC 驱动；测试源码在运行期加载驱动，因此运行命令必须带驱动 jar。

### 4.2 运行单元测试（57 条）

Linux / macOS：

```bash
java -cp "build/main:build/test:lib/mysql-connector-j-8.2.0.jar" com.chat.test.TestRunner
```

Windows：

```powershell
java -cp "build\main;build\test;lib\mysql-connector-j-8.2.0.jar" com.chat.test.TestRunner
```

也可以只跑某个测试类：

```bash
java -cp "build/main:build/test:lib/mysql-connector-j-8.2.0.jar" \
     com.chat.test.TestRunner com.chat.test.FileServiceTest
```

### 4.3 运行集成测试（10 条）

```bash
java -cp "build/main:build/test:lib/mysql-connector-j-8.2.0.jar" com.chat.test.IntegrationTest
```

集成测试会真实启动服务器、创建客户端、收发消息与文件，单次执行约十几秒。它同样读取 `config/chat.properties`，但数据库被 `TestDatabase` 指向 `lanchat_test`。

### 4.4 指定其他测试库

```bash
java -Dlanchat.test.db.url="jdbc:mysql://localhost:3306/lanchat_test_2?useSSL=false&serverTimezone=Asia/Shanghai&createDatabaseIfNotExist=true&characterEncoding=utf8" \
     -cp "build/main:build/test:lib/mysql-connector-j-8.2.0.jar" com.chat.test.TestRunner
```

系统属性必须写在 `-cp` 之前（JVM 参数顺序），且要在 `Config` 第一次加载前生效。

### 4.5 在 IntelliJ IDEA 中运行

1. 用 IDEA 打开项目根目录（直接包含 `src`、`lib`、`config` 的那一层）。
2. `File -> Project Structure`：SDK 选 JDK 17+；`src/main/java` 标记为 Sources Root，`src/test/java` 标记为 Test Sources Root；`lib/mysql-connector-j-8.2.0.jar` 加入依赖。
3. 新建两个 Application 运行配置：
   - 单元测试：Main class `com.chat.test.TestRunner`，工作目录为项目根目录；
   - 集成测试：Main class `com.chat.test.IntegrationTest`，工作目录为项目根目录。
4. 运行配置的 **Working directory 必须是项目根目录**，否则读不到 `config/chat.properties`。

> 仓库内 `.idea/` 与 `*.iml` 按惯例不入库，换机器后需要重新导入一次，属正常现象。

### 4.6 输出怎么读

单元测试输出形如：

```
========== 单元测试开始 ==========

--- SecurityUtilTest ---
  [通过] 盐值生成：长度 32 且两次生成不同
  ...
========== 测试汇总 ==========
执行用例: 57
通过: 57
跳过: 0
失败: 0
结论: 全部通过
```

集成测试输出形如：

```
========== 集成测试汇总 ==========
用例总数: 10
通过: 10
失败: 0
结论: 全部通过
```

三种状态的含义：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| 通过 | 用例内全部断言成立 | 无 |
| 跳过 | 环境不满足（通常是数据库连不上），不是代码失败 | 按 `TestDatabase.unavailableReason()` 修复环境后重跑 |
| 失败 | 断言不成立或抛出非预期异常 | 按输出的用例名与原因定位 |

注意：数据库不可用时集成测试会打印"结论: 已跳过"并以 0 退出。**不能只看退出码**，必须看汇总里的"通过/失败/跳过"数字。

### 6.1 集成测试的两个关键设计

**缓冲监听器**：服务器推送的上线通知与用户列表往往在测试开始等待之前就已到达。若等到需要时才注册监听器，会稳定错过。`BufferingListener` 在客户端连接的第一时间注册并缓存全部消息，断言只在缓存中检索，从根上消除竞态。

**按条数断言**：`await` 每次从头扫描，只要存在一条旧命中就立即返回，因此"又收到一条相同消息"不能靠 `await`，必须用 `count` 数条数。

### 6.2 测试数据与清理

- 预置用户由测试自己写入，测试结束调用 `shutdown()` 停止服务器与全部客户端；
- 临时目录递归删除；
- 测试库中的两张表在下一个用例开始前再次清空，不依赖"上一个用例收尾干净"。

## 八、判定标准

一次测试可判定为通过，必须同时满足：

1. 主源码与测试源码编译 0 错误；
2. 单元测试输出 **通过 57、失败 0、跳过 0**；
3. 集成测试输出 **用例总数 10、通过 10、失败 0**；
4. 同一份代码连续执行两次，结果一致（排除偶发竞态）；
5. 测试库中不残留 `chat_user` / `chat_message` 的业务数据（测试自行清理）。

出现"跳过"时不算通过，必须先修复环境再重跑。需要记录结果时，建议保存运行输出到自己的验收材料中，而不是写回本文件。

## 九、常见问题

**Q1：单元测试大量跳过，提示"无法连接测试库"**

检查 MySQL 是否启动、`config/chat.properties` 的 `db.*` 是否正确、账号是否有建库权限。可先用同一个账号执行 `mysql -u 用户名 -p -e "CREATE DATABASE IF NOT EXISTS lanchat_test"` 手工验证。

**Q2：提示"未找到 JDBC 驱动"**

运行命令的类路径缺少 `lib/mysql-connector-j-8.2.0.jar`。编译测试源码与运行测试都必须带它。

**Q3：集成测试端口冲突**

集成测试用 `ServerSocket(0)` 自动分配端口，正常不会冲突。若失败信息指向端口，检查是否有残留的测试 JVM 未退出，结束进程后重跑。

**Q4：历史查询日期不对**

`db.url` 的 `serverTimezone` 填错。见 3.4。

**Q5：集成测试卡住或超时**

先确认 `ai.bot.id` / `ai.api.token` 为空。配置了真实令牌时，小助手会注册为虚拟成员并可能发起外部 HTTP 请求；虽然服务器行为仍然正确，但测试环境无外网时会拖慢启动。集成测试不依赖小助手，建议留空。

**Q6：Windows 上路径分隔符**

编译与运行的 classpath 用分号 `;`，Linux/macOS 用冒号 `:`。本文两套命令都已给出。

**Q7：输出中文乱码**

编译必须加 `-encoding UTF-8`；控制台代码页建议 UTF-8。数据库连接串带 `characterEncoding=utf8`。

## 十、维护约定

1. 新增功能必须同时新增用例，并在本文件登记编号、输入、预期；只改代码不登记视为未完成。

6. 修改协议字段、数据库列或消息类型时，必须检查受影响的用例是否仍能表达原意，不能只把断言改成"能跑通"。
