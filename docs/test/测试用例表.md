本文档逐条列出本项目全部自动化测试用例，共 **68 条**，其中单元测试 **47 条**、集成测试 **7 条**、
界面走查 **14 条**（在 Xvfb 虚拟显示中由 `java.awt.Robot` 驱动真实窗口执行，非人工目测）。
表中"实际结果"与"是否通过"两列取自真实运行输出，未做任何修饰；凡未实际执行的项均明确标注"未执行"或"未自动化覆盖"，不以推测值填充。

## 一、编号规则与判定口径

| 项目 | 说明 |
| --- | --- |
| 用例编号 | 单元测试：`UT-<模块>-<序号>`；集成测试：`IT-<序号>`；界面走查：`UI-<序号>` |
| 模块缩写 | `SEC` 密码安全工具；`DAO` 用户数据访问；`SVC` 用户业务服务；`MSG` 消息与持久化；`FILE` 文件传输；`IT` 端到端集成；`UI` 界面走查 |
| 用例名称 | 与源码中 `@Test("...")` 注解文本完全一致，便于与运行输出逐行核对（界面走查一项对应脚本中的一条 `check(...)` 断言） |
| 执行方式 | 单元测试由 `TestRunner` 反射执行（方法名字典序）；集成测试由 `IntegrationTest.main` 顺序执行；界面走查由走查脚本在 Xvfb 虚拟显示中顺序执行 |
| 通过判定 | 用例内全部断言成立即通过；任一断言抛出 `AssertionError` 即失败 |
| 不稳定判定 | 同一份代码多次复跑出现"通过/失败"不一致者，判定为不稳定，按未通过计入 |
| 数据快照 | 2026-09-19，JDK 21.0.12，Ubuntu 24.04.4 LTS，测试网络为本机回环 127.0.0.1 |

以下条目在需求中存在，但当前自动化测试未覆盖或仅部分覆盖，未在本文档中标记为"通过"，以避免虚增通过率。对应关系与建议补充方式见《测试报告》第八节需求覆盖矩阵与第九节缺陷记录。

| 需求编号 | 需求摘要 | 当前覆盖情况 | 建议补充方式 |
| --- | --- | --- | --- |
| FR-1 | 局域网 UDP 自动发现 | 未自动化覆盖（集成测试直接使用 127.0.0.1 与已知端口） | 补充双进程 UDP 发现测试，或纳入手工测试 |
| FR-12 / NFR-6 | 心跳掉线检测 60 至 80 秒 | 仅通过 IT-06 间接覆盖主动断开，未覆盖"进程被强杀"场景 | 补充杀进程实验并计时 |
| FR-13 | 服务器 Swing 控制台 | 界面走查 UI 系列已覆盖窗口形态与启动按钮，未覆盖端口占用等失败路径 | 补充端口占用场景的界面走查 |
| FR-16 | 单条消息不超过 2000 字符 | 未自动化覆盖 | 补充客户端发送端校验用例 |

| NFR-5 | 客户端启动 3 秒内可见登录窗口 | 界面走查中登录窗口均在 1 秒内出现，但未做正式计时 | 补充启动计时断言 |

## 七、运行命令

```bash
# 运行全部测试（单元 + 集成）
./scripts/test.sh all

# 仅运行单元测试（47 条）
./scripts/test.sh unit

# 仅运行集成测试（7 条）
./scripts/test.sh integration
```

等价的手工命令（本文档所有实测数据均由此命令产生）：

```bash
# 编译
javac -encoding UTF-8 -d build/classes $(find src/main/java -name '*.java')
javac -encoding UTF-8 -cp build/classes -d build/test-classes $(find src/test/java -name '*.java')

# 单元测试
java -cp build/classes:build/test-classes com.chat.test.TestRunner

# 集成测试
java -cp build/classes:build/test-classes com.chat.test.IntegrationTest
```

退出码约定：0 表示全部通过，非 0 表示存在失败用例，可直接被脚本或持续集成判断。

界面走查不通过 `scripts/` 提供入口（走查脚手架只用于取证，不属于交付源码），执行方式为：
在虚拟显示中运行走查程序，程序自行启动服务器与窗口，逐项输出 `[通过]` / `[失败]` 与截图文件名；
若出现"界面线程无响应"，程序会打印线程转储后继续执行，最终汇总输出"检查项: 14，失败: 0，结论: 全部通过"。

## 八、维护约定

1. 新增用例必须同时更新本表与本文件第二列的用例名称，保持与 `@Test("...")` 注解文本一致。
2. 用例编号一经分配不再复用，删除用例时标注"已废弃"而非删除行。
3. 每次修改测试结果后必须重新运行并据实更新"实际结果"与"是否通过"，禁止以历史值填充。
4. 不稳定用例必须记录复跑次数与失败/通过分布，不得只保留最后一次结果。
